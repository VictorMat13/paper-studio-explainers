## Body A: What it actually is (the reel's structure, explained plainly)

**[Git]**
GitHub runs on Git, the version control tool almost every developer uses.

**[Commit]**
Here's how it works. Every time you save your progress, that's called a commit.

**[Snapshot]**
It's a snapshot of every file in your project, linked to the one before it.

**[Timeline]**
Line them up, and that's your app's timeline.

**[Go back]**
So when a prompt breaks something, you tell Claude to go back to the last version that worked.

**[Laptop]**
But that timeline only lives on your laptop. If that dies, it's gone.

**[Push]**
So you push it to GitHub, and the whole history lives online.

**[Clone]**
Grabbing a tool from there does the same thing in reverse. Cloning copies its entire timeline onto your computer.

**[Branch]**
Want to try a new feature without risking the version that works? Make a branch, a second timeline that splits off.

**[Merge]**
If it turns out well, you merge it back in. If not, you delete it.

**[Tag]**
And when a version is solid, tag it, like v1, so you can come back to it anytime.

**[Claude]**
If you're new to building with AI, just tell Claude to commit and push. It runs the commands for you.

## Body C: What goes wrong without it (problem first)

**[Problem]**
Here's the problem. Most people building with AI have one copy of their app, on one laptop, and every request rewrites it.

**[Break]**
So a prompt breaks something, and there's no way back to the version from an hour ago.

**[Dies]**
Or the laptop dies, and the whole project goes with it.

**[Fix]**
GitHub fixes both. Every commit is a snapshot of your entire project, so a bad prompt is one step back.

**[Online]**
Push sends that history online, so a dead computer costs you nothing.

**[Tag]**
And when a version is solid, tag it v1, so you can always get back to it.

**[Branch]**
A branch gives a risky idea its own copy to play in. If it works out, you merge it in, and if it flops, you throw it away.

**[Claude]**
